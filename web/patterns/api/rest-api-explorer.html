Act 01

Lạc hậu tài liệu (API Drift) & Rào cản chạy thử

Trong phát triển phần mềm Agile và microservices, API liên tục thay đổi. Sự thiếu đồng bộ giữa tài liệu thiết kế (Word, Excel) và code triển khai thực tế luôn là nguyên nhân hàng đầu gây lỗi tích hợp hệ thống.

📝

Tài liệu tĩnh lạc hậu

Các tài liệu API viết tay trên Wiki hoặc Word nhanh chóng bị lỗi thời ngay khi backend sửa tên trường hoặc đổi URL path. Developer phải liên tục trao đổi để kiểm chứng cấu hình payload thực tế.

⚠️

Lỗi đồng bộ (API Drift)

Sự sai lệch giữa đặc tả trên giấy và thực tế code dẫn đến lỗi Runtime khi Frontend gọi Endpoint. Các lỗi này thường chỉ phát hiện muộn ở giai đoạn Staging/UAT, gây trễ tiến độ release.

🔌

Cô lập và Khó thử nghiệm

Frontend Dev hoặc đối tác tích hợp muốn test API phải cài đặt Postman, xin cấp quyền, cấu hình token thủ công phức tạp. Thiếu một môi trường thử nghiệm nhanh (Sandbox) để thao tác tức thì.

🚨

KBLab Incident — Chậm tiến độ 2 ngày do Endpoint bị thay đổi ngầm

Khi tích hợp module chấm bài tự động, Frontend gọi API POST /api/question theo file đặc tả Word lưu hành nội bộ. Tuy nhiên, Backend đã đổi endpoint sang POST /api/v1/questions (thêm phiên bản v1 và số nhiều) để tuân thủ thiết kế RESTful. Do thiếu tài liệu tập trung tự động cập nhật, Frontend nhận lỗi 404 liên tục và mất 2 ngày để debug, map lại API.

Act 02

OpenAPI Specification & Swagger UI Sandbox

OpenAPI Specification (OAS): Là chuẩn mô tả API RESTful độc lập với ngôn ngữ lập trình. Nó cho phép cả con người và máy tính hiểu được cấu trúc API (Endpoints, Parameters, Payloads, Security) mà không cần truy cập trực tiếp vào source code.
Swagger UI / API Explorer: Tự động biên dịch tài liệu OpenAPI thành giao diện web tương tác, tích hợp sẵn Sandbox (nút "Try it out") để chạy thử API real-time.

— OpenAPI Initiative & SmartBear Software

Với cơ chế tài liệu hóa tự động từ code (Code-First), mã nguồn đóng vai trò là Source of Truth duy nhất. Mỗi khi code thay đổi, tài liệu API sẽ tự động cập nhật theo thời gian thực.

Thành phần 01

Backend Annotations

Metadata được tích hợp trực tiếp vào Controller/DTO (như @Operation, @Schema). Đảm bảo code và tài liệu luôn đồng bộ.

Thành phần 02

OpenAPI Spec Generator

Công cụ (như Springdoc) quét qua mã nguồn lúc runtime/buildtime để sinh ra file đặc tả dạng JSON/YAML chuẩn hóa.

Thành phần 03

Interactive Sandbox

Swagger UI hiển thị trực quan các nhóm endpoint, cấu trúc request/response mẫu, tích hợp sẵn REST Client để thực thi request.

Richardson Maturity Model — Định hướng thiết kế API KBLab

      

        Đánh giá và nâng cấp độ trưởng thành API theo mô hình Richardson để đảm bảo chuẩn hóa RESTful:
      

      

        

          
Level 0

          
Swamp of POX

          
Gọi duy nhất endpoint POST để truyền bản tin XML/RPC.

        

        

          
Level 1

          
Resources

          
Phân rã URI riêng cho từng tài nguyên (e.g. /questions).

        

        

          
Level 2 ✓ Target

          
HTTP Verbs

          
Sử dụng đúng HTTP Method & HTTP Status Code chuẩn hóa.

        

        

          
Level 3

          
HATEOAS

          
Đính kèm link điều hướng trạng thái tiếp theo trong phản hồi.

        

      

    


    
    
Phân tích sai lệch và Khắc phục tại KBLab

    
Bảng đối chiếu khoảng cách (Gap Analysis) và chuẩn hóa API

    
    

      
        

          API Category
          Khuyết tật API hiện tại
          Phương án Chuẩn hóa (OpenAPI & REST)
        

      
      
        

          API Versioning
          Thiếu thống nhất. Một số endpoint cũ không có version, gây rủi ro crash app client khi thay đổi DB schema.
          Bắt buộc khai báo tiền tố /api/v1/ cho toàn bộ các endpoint. Cấu hình versioning qua path.
        

        

          Resource Naming
          Đặt tên tùy tiện, trộn lẫn số ít/nhiều (e.g. /api/question vs /api/users).
          Chuẩn hóa tên URI bằng danh từ số nhiều mô tả resource (e.g. /api/v1/questions).
        

        

          Error Response
          Trả về status 200 OK kèm thông báo lỗi dạng text, hoặc cấu trúc JSON lỗi không thống nhất.
          Định nghĩa cấu trúc lỗi chung (timestamp, status, error, message, path). Ném HTTP Status thích hợp (4xx/5xx).
        

        

          Security Header
          Để lộ cơ chế sinh token hoặc chấp nhận request không chứa token tại các endpoint quản trị.
          Bắt buộc lọc JWT qua Gateway, chặn role STUDENT truy cập các endpoints viết hoặc xóa dữ liệu admin.
        

      
    


    
    
Lộ trình triển khai tự động hóa tài liệu API

    
Quy trình 3 bước chuẩn hóa API tích hợp CI/CD


    

      

        

        
Phase 01

        
Chuẩn hóa cấu trúc Route & DTO Design

        

          Thiết lập cấu trúc Endpoint chuẩn RESTful. Xây dựng lớp DTO (Data Transfer Object) để tách biệt thực thể Database khỏi dữ liệu JSON trả về client, ngăn rò rỉ thông tin nhạy cảm.
        

        Hoàn tất thiết kế
      


      

        

        
Phase 02

        
Tích hợp Springdoc OpenAPI Starter

        

          Thêm dependency springdoc-openapi-starter-webmvc-ui vào các file pom.xml. Gắn annotation @Tag, @Operation, @Schema trong Controller để tự động sinh file mô tả OpenAPI JSON tại Runtime.
        

        Đang thực hiện
      


      

        

        
Phase 03

        
Đồng bộ Portal API tại API Gateway

        

          Cấu hình API Gateway thu thập (aggregate) các file OpenAPI JSON từ tất cả các microservices con độc lập. Trình diễn một giao diện Swagger UI tập trung duy nhất tại Gateway portal cho toàn bộ lập trình viên.
        

        Chờ kiểm thử
      

    


    
    
Quy tắc thiết kế API tại KBLab

    

      

        

          
✅

          
Nên làm (Best Practices)

        

        
    
          
  • Sử dụng danh từ số nhiều cho URI: /api/v1/submissions.
    • 
          
  • Khai báo đầy đủ HTTP Status Code trong OpenAPI annotation (200, 201, 204, 400, 401, 403, 404).
    • 
          
  • Kích hoạt Swagger Sandbox trên môi trường Dev/Staging để hỗ trợ test nhanh.
    • 
          
  • Sử dụng DTO để giới hạn các thuộc tính hiển thị (như ẩn mật khẩu, ẩn mối quan hệ vòng DB).
    • 
        

      

      

        

          
❌

          
Không nên làm (Anti-patterns)

        

        
    
          
  • Cấu hình bật Swagger UI công khai trên môi trường Production (nguy cơ bị quét lộ hổng bảo mật).
    • 
          
  • Sử dụng động từ trong đường dẫn: /api/v1/deleteQuestion thay vì dùng đúng HTTP DELETE.
    • 
          
  • Trả về HTTP status 200 OK cho các lỗi hệ thống hoặc xác thực.
    • 
          
  • Thay đổi kiểu dữ liệu payload mà không nâng cấp phiên bản API (api versioning).
    •
