Act 01

The Problem

Khi frontend (Web/Mobile) cần hiển thị dữ liệu phân cấp (VD: danh sách bài tập, đi kèm danh sách nộp bài của từng bài tập), việc sử dụng REST API truyền thống bộc lộ nhiều hạn chế.

🐢

N+1 Network Roundtrips

Client gọi 1 request lấy danh sách N bài tập, sau đó phải gọi thêm N request độc lập để lấy lượt nộp bài tương ứng. Tổng cộng N+1 network requests, gây latency cao trên kết nối chậm (3G/4G).

📦

Over-fetching

REST endpoint thường trả về toàn bộ fields của entity. Frontend chỉ cần tiêu đề và điểm số, nhưng lại nhận được cả source code, logs... Điều này làm tăng kích thước payload, lãng phí bandwidth.

2
Act 02

The Pattern

GraphQL: Cung cấp single endpoint. Client gửi Query DSL xác định chính xác cấu trúc và fields cần thiết. Server trả về đúng payload yêu cầu trong 1 request.
DataLoader: Cơ chế batching và caching ở server. Ngăn chặn việc đẩy bài toán N+1 từ network xuống database (SQL N+1).

— GraphQL Architecture · Facebook (2015)

Sử dụng DataLoader, các DB query rời rạc trong Resolver được batching thành 1 câu SQL IN (?,?,...) duy nhất để tối ưu performance.

Thành phần 01

Single Endpoint

Client gọi POST /graphql với Query JSON định nghĩa chính xác data schema.

Thành phần 02

Field Resolvers

Hàm xử lý fetch dữ liệu cho từng field trong Schema, cho phép tổng hợp data từ nhiều nguồn (DB, Cache, REST APIs).

Thành phần 03

DataLoader Batching

Hoãn thực thi các câu SQL đơn lẻ, gom nhóm IDs từ các Parent Resolvers để chạy 1 batch query, loại bỏ N+1 Database problem.

KBM: Apply It

KBM triển khai GraphQL BFF (Backend-for-Frontend) làm data aggregator cho giao diện Web/Mobile.

GraphQL Deployment Roadmap

Các bước tích hợp GraphQL
Phase 1 · Tuần 1

Define Schema & Queries

Khởi tạo Spring Boot GraphQL. Định nghĩa schema.graphqls mô tả types: Assignment, Submission, User và queries.

Dự kiến: 1 dev × 3 ngày
Phase 2 · Tuần 2

Implement Resolvers

Implement Controller Resolvers mapping tới Repositories. Test qua GraphiQL playground.

✓ Hoàn thành các query lấy dữ liệu cơ bản
Phase 3 · Tuần 3

Optimize Database with DataLoader

Đăng ký DataLoader bean. Thay thế single DB queries bằng batching (IN (?,?,...)) để chặn N+1 queries.

Dự kiến: 1 dev × 4 ngày
Phase 4 · Tuần 4

Query Complexity Limiting

Ngăn chặn nested queries (VD: A->B->A->B...). Cấu hình MaxQueryDepthInstrumentation (Max depth = 5) chống DDoS.

✓ Hệ thống API GraphQL an toàn hoạt động 100%

Use Cases / Anti-patterns

✓
Use cases
  • Xây dựng Backend-for-Frontend (BFF) phục vụ đa client (Web, Mobile).
  • Data model phân cấp sâu, quan hệ phức tạp.
  • Ứng dụng mobile cần tối ưu network payload (bandwidth-constrained).
  • Yêu cầu UI linh hoạt, tránh API versioning liên tục.
✗
Anti-patterns
  • CRUD đơn giản, data phẳng (REST là đủ).
  • Xử lý File Upload/Download nhị phân lớn.
  • Yêu cầu HTTP/CDN caching (GraphQL dùng POST, khó cache native).
  • Hệ thống public API không kiểm soát được query complexity (nguy cơ DDoS).
