Act 01

The Problem

Khi mở rộng lên hàng chục microservices, việc lưu file cấu hình (database URL, credentials, timeouts) cục bộ trong từng container gây khó khăn lớn cho quá trình vận hành.

[Down Trend]

Configuration Drift

Các môi trường (Dev, Staging, Prod) yêu cầu tham số khác nhau. Lưu cấu hình cục bộ dễ dẫn đến sai sót khi deploy (VD: quên đổi tham số trên Staging, vô tình kết nối nhầm DB Production).

[Error]

Rebuild & Restart Overhead

Điều chỉnh một tham số nhỏ (VD: tăng Connection Pool size, giảm Timeout) đòi hỏi sửa file, build lại JAR và restart toàn bộ container, gây downtime không đáng có.

2
Act 02

The Pattern

Sử dụng Config Server kết nối với Git Repository chứa toàn bộ file cấu hình. Microservices truy vấn Config Server lúc khởi động để tải cấu hình theo Profile. Khi có thay đổi, chỉ cần push lên Git và trigger Bus refresh để hot-reload cấu hình cho các downstream services mà không cần restart.

— Centralized Configuration · Spring Cloud Config & Bus

Spring Cloud Bus kết hợp Message Broker (VD: Kafka) broadcast tín hiệu refresh cấu hình đến mọi service instance gần như tức thời.

Thành phần 01

Git Config Repo

Centralized repository chứa các file YAML (VD: application-prod.yml). Được quản lý bằng Git version control, dễ dàng audit và rollback cấu hình.

Thành phần 02

Config Server

Middle service đọc cấu hình từ Git và expose qua REST API (định dạng JSON). Hỗ trợ mã hóa (encryption) cho các thông tin nhạy cảm (credentials, tokens).

Thành phần 03

Spring Cloud Bus (Reload)

Message bus đồng bộ cấu hình. Khi gọi API /actuator/busrefresh, một event được đẩy lên Kafka, yêu cầu toàn bộ client hot-reload cấu hình.

Act 04 — Case Study

KBM: Apply It

Config Server giúp KBM đảm bảo tính nhất quán (consistency) cấu hình xuyên suốt các môi trường mà không gây gián đoạn hệ thống.

Configuration Management Solutions Comparison

Tiêu chí Local Hardcoded Configuration Spring Cloud Config Server Kubernetes ConfigMap/Secret
Lưu trữ tập trung Không (Lưu phân tán). Có (Lưu tại Git Repository). Có (Lưu tại K8s etcd).
Hot Reload Không (Yêu cầu rebuild & restart). Hỗ trợ tốt (Qua Kafka Bus Refresh). Có (Yêu cầu ứng dụng có cơ chế file-watching).
Bảo mật dữ liệu nhạy cảm Kém (Clear text trong source code). Cao (AES/RSA encryption). Cao (K8s Secret, RBAC).
Môi trường triển khai (KBM) Deprecated. Local Development (Docker Compose). Production (Kubernetes).

Config Server Deployment Roadmap

Các bước chuẩn hóa configuration
Phase 1 · Tuần 1

Khởi tạo Git Config Repository

Tạo private Git repo chứa các file application*.yml. Migrate toàn bộ local properties của các service sang repo này.

Dự kiến: 1 dev × 2 ngày
Phase 2 · Tuần 2

Deploy Config Server Project

Khởi tạo Spring Boot Config Server project. Cấu hình kết nối SSH tới Git Repo. Bật annotation @EnableConfigServer và verify REST API.

✓ Verify cấu hình JSON qua API thành công
Phase 3 · Tuần 3

Tích hợp Spring Cloud Bus với Kafka

Tích hợp spring-cloud-starter-bus-kafka vào downstream services. Gắn annotation @RefreshScope cho các config bean để hỗ trợ hot-reload.

Dự kiến: 1 dev × 3 ngày
Phase 4 · Tuần 4

Sensitive Data Encryption

Cấu hình JCE (Java Cryptography Extension) trên Config Server. Mã hóa mật khẩu DB thành format {cipher}*** trên Git, ngăn ngừa lộ lọt credentials.

✓ Triển khai Secure Configuration & Hot Reload thành công

Use Cases / Anti-patterns

✓
Use cases
  • Hệ thống có nhiều microservices độc lập.
  • Triển khai đa môi trường (Dev, Staging, Prod).
  • Cần điều chỉnh runtime parameters thường xuyên (timeout, threadpool size).
  • Yêu cầu centralized configuration, version control và audit logging qua Git.
✗
Anti-patterns
  • Monolith hoặc hệ thống đơn giản (over-engineering).
  • Môi trường Cloud-Native 100% Kubernetes (Nên dùng K8s ConfigMap/Secret).
  • Thiếu hạ tầng Private Git repository an toàn.
  • Team chưa có kinh nghiệm vận hành asynchronous Event Bus/Message Broker.
