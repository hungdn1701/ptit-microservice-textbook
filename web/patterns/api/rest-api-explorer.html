Act 01

The Problem

API thay đổi liên tục trong môi trường Agile/Microservices. Thiếu đồng bộ giữa tài liệu thiết kế (Word, Excel) và code triển khai là nguyên nhân chính gây lỗi tích hợp.

[Documentation]

Outdated Static Documentation

Tài liệu API tĩnh trên Wiki/Word nhanh chóng lỗi thời khi backend thay đổi fields hoặc URL paths. Developers mất thời gian trao đổi để đối chiếu payload thực tế.

[Warning]

API Drift

Sai lệch giữa spec và code gây lỗi Runtime khi Frontend tích hợp. Thường chỉ phát hiện ở Staging/UAT, gây trễ release.

[Connection]

Testing Barriers

Test API yêu cầu cài đặt Postman, xin quyền, setup token phức tạp. Thiếu môi trường Sandbox tích hợp để thử nghiệm nhanh.

2
Act 02

The Pattern

OpenAPI Specification (OAS): Chuẩn mô tả RESTful API language-agnostic. Giúp con người và máy tính đọc hiểu cấu trúc API (Endpoints, Parameters, Payloads, Security) không cần source code.
Swagger UI / API Explorer: Render OAS thành interactive web interface, tích hợp Sandbox (Try it out) để test API real-time.

— OpenAPI Initiative & SmartBear Software

Áp dụng mô hình Code-First, mã nguồn trở thành Source of Truth duy nhất. Tài liệu API được tự động sinh và cập nhật real-time theo code.

Thành phần 01

Backend Annotations

Sử dụng annotations (@Operation, @Schema) trực tiếp trên Controller/DTO để nhúng metadata, đảm bảo spec và code luôn đồng bộ.

Thành phần 02

OpenAPI Spec Generator

Công cụ (VD: Springdoc) quét mã nguồn (runtime/build-time) để sinh file OAS JSON/YAML.

Thành phần 03

Interactive Sandbox

Swagger UI hiển thị endpoints, request/response schema, và tích hợp REST Client để execute request.

Richardson Maturity Model

      

        Đánh giá mức độ trưởng thành của API theo mô hình Richardson:
      

      

        

          
Level 0

          
Swamp of POX

          
Sử dụng single POST endpoint để truyền XML/RPC payload.

        

        

          
Level 1

          
Resources

          
Phân rã URI theo từng resource (VD: /questions).

        

        

          
Level 2 ✓ Target

          
HTTP Verbs

          
Sử dụng đúng HTTP Methods (GET, POST, PUT, DELETE) & HTTP Status Codes.

        

        

          
Level 3

          
HATEOAS

          
Đính kèm hypermedia links điều hướng trạng thái trong response.

        

      

    


    
    
KBM API Gap Analysis & Remediation

    
Gap Analysis & Standardization Table

    
    

      
        

          API Category
          Current API Flaws
          Standardization Strategy
        

      
      
        

          API Versioning
          Inconsistent. Thiếu versioning gây rủi ro breaking changes cho clients.
          Bắt buộc URI prefix /api/v1/ (Path versioning).
        

        

          Resource Naming
          Inconsistent naming, trộn lẫn số ít/nhiều (VD: /api/question vs /api/users).
          Chuẩn hóa bằng danh từ số nhiều (VD: /api/v1/questions).
        

        

          Error Response
          Luôn trả 200 OK cho lỗi, cấu trúc JSON error thiếu đồng nhất.
          Chuẩn hóa error format (timestamp, status, message, path). Sử dụng đúng 4xx/5xx HTTP Status.
        

        

          Security Header
          Thiếu security schemas trên endpoint nhạy cảm.
          Cấu hình JWT authentication & Role-based Access Control (RBAC) tại Gateway.

API Design Guidelines

    

      

        

          
✓

          
Best Practices

        

        
    
          
  • Sử dụng danh từ số nhiều cho URI (VD: /api/v1/submissions).
    • 
          
  • Define rõ HTTP Status Codes trong OAS annotations.
    • 
          
  • Bật Swagger UI trên Dev/Staging environments.
    • 
          
  • Sử dụng DTOs để ẩn field nhạy cảm và xử lý circular references.
    • 
        

      

      

        

          
✗

          
Anti-patterns

        

        
    
          
  • Expose Swagger UI trên Production (security risk).
    • 
          
  • Sử dụng động từ trong path (VD: /api/v1/deleteQuestion thay vì DELETE).
    • 
          
  • Trả về 200 OK cho system/auth errors.
    • 
          
  • Breaking schema changes mà không bump API version.
    •
