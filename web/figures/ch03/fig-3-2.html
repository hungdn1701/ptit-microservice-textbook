Thay đổi API thuộc loại nào?
Backward Compatible
• thêm field mới (optional)
• thêm endpoint mới
• thêm giá trị enum mới
consumer cũ bỏ qua field lạ
Breaking Change
• xóa field hiện có
• đổi tên field
• đổi kiểu dữ liệu field
• đổi URL endpoint
consumer cũ sẽ lỗi
Chiến lược versioning khi buộc phải có breaking change
URL Path
/api/v1/users → /api/v2/users
dễ test, rõ ràng, phổ biến nhất — KBM dùng cách này
Header
Accept: application/vnd.v2+json
RESTful hơn, URL gọn
Query Param
/api/users?version=2
