Sự trùng lặp mã nguồn & Lỗ hổng bảo mật

Thiếu API Gateway, các microservice nội bộ phải tự xử lý các tác vụ cross-cutting concerns (CORS, JWT validation, rate limiting, routing). Điều này gây khó khăn lớn trong phát triển và vận hành.

[Config]

Trùng lặp logic & Khó bảo trì (Boilerplate code)

Nhiều service phải cài đặt thư viện và viết filter giải mã JWT tương tự nhau. Khi cập nhật thuật toán mã hóa (VD: HS256 sang RS256) hoặc đổi Secret Key, cần cập nhật cấu hình và redeploy toàn bộ service.

[Unlocked]

Rủi ro bảo mật & Inconsistent CORS

Các microservice tự quản lý CORS dễ dẫn đến sai lệch cấu hình. Một cấu hình Allow-Origin: * nhầm lẫn có thể mở ra lỗ hổng. Ngoài ra, cấu hình CORS không đồng nhất gây lỗi preflight request trên trình duyệt.

Act 02

API Gateway Routing Pipeline

Sử dụng API Gateway làm single entry point. Thực thi Filter Chain tập trung (CORS, JWT validation, rate limiting) trước khi routing. Gateway giải mã token, chèn user context (User ID, Roles) vào HTTP header, và forward request xuống các downstream service.

— API Gateway Routing · Microservice Patterns (Chris Richardson)

Pattern này đưa các internal service vào Private Network, đảm bảo stateless và tập trung 100% vào business logic, tách biệt hoàn toàn khỏi security infrastructure.

Thành phần 01

Routing Predicates

Điều kiện match URL pattern (VD: /api/v1/courses/**) để xác định downstream service thông qua Service Discovery.

Thành phần 02

Pre/Post Filter Chain

Filter thực thi trước (Pre) và sau (Post) quá trình routing. Pre-filter xử lý JWT validation, logging, rate limiting. Post-filter bổ sung response header, tracking latency, hoặc data compression.

Thành phần 03

Gateway-to-Service Trust

Sau khi JWT validation thành công, Gateway inject các header X-User-Id và X-User-Roles. Các downstream service chỉ đọc các header này và hoàn toàn tin tưởng Gateway (không cần re-validate JWT).

Lộ trình triển khai Gateway

Gateway Deployment Roadmap
Phase 1 · Tuần 1

Xây dựng Gateway Core & Cấu hình Routes YAML

Khởi tạo Spring Cloud Gateway (WebFlux reactive engine, non-blocking). Cấu hình routing rule tới internal service qua Eureka Service Registry.

Dự kiến: 1 dev × 3 ngày
Phase 2 · Tuần 2

Viết Custom Global JWT Filter & Header Injection

Implement JwtRequestFilter. Xác thực JWT (RSA public key), trích xuất userId, roles, và inject vào HTTP Header để forward an toàn xuống downstream.

✓ Loại bỏ hoàn toàn JWT logic ở downstream service
Phase 3 · Tuần 3

Cấu hình CORS & Cảnh báo an toàn an ninh

Cấu hình Global CORS tại Gateway, xóa CORS ở downstream. Bổ sung HTTP Security Headers (X-Content-Type-Options, X-Frame-Options, Content-Security-Policy).

Dự kiến: 1 dev × 2 ngày
Phase 4 · Tuần 4

Đồng bộ bảo mật mạng nội bộ (mTLS / Network Policy)

Chỉ cho phép downstream service nhận traffic từ Gateway. Cấu hình Kubernetes NetworkPolicy hoặc Security Group để block mọi direct access từ Internet.

✓ Thiết lập thành công Trusted Private Network

Khi nào dùng — Khi nào không

✓
Use cases
  • Kiến trúc gồm nhiều microservices độc lập.
  • Phục vụ đa dạng client (Web, Mobile, Third-party).
  • Cần quản lý tập trung security, CORS, rate limiting, access log.
  • Che giấu internal network topology, phòng chống port scanning attack.
✗
Anti-patterns
  • Monolith hoặc hệ thống đơn giản (tránh over-engineering).
  • Ứng dụng truyền tải file siêu lớn (nguy cơ network bottleneck tại Gateway).
  • Yêu cầu ultra-low latency (Gateway overhead ~1-3ms).
  • Các microservices hoàn toàn độc lập, không dùng chung authentication mechanism.
