Act 01

The Problem

Trong Microservices, các Service Instances rất linh hoạt. Việc liên tục scale-up, scale-down, restart, hoặc crash khiến IP và Port của chúng thay đổi liên tục.

[Network]

Hardcoded IP Configurations

Nếu Service A hardcode IP của Service B (VD: trong application.properties), hệ thống sẽ lỗi khi B đổi IP hoặc di chuyển. Bảo trì đòi hỏi sửa config và redeploy toàn bộ.

[Error]

No Automated Scale-Out

Khi Service B scale-out thêm instances để gánh tải, Service A không nhận biết được các IPs mới. Client-side Load Balancing bị vô hiệu hóa.

2
Act 02

The Pattern

Triển khai Service Registry (VD: Netflix Eureka). Khi khởi động, instance tự động đăng ký thông tin (Tên service, IP, Port) với Registry (Service Registration). Các Client sẽ query Registry để lấy danh sách active IPs và gọi trực tiếp (Service Discovery).

— Service Discovery Pattern · Microservice Patterns (Chris Richardson)

Eureka sử dụng cơ chế Heartbeat định kỳ. Nếu instance ngừng gửi heartbeat, Eureka đánh dấu là down và gỡ khỏi registry.

Thành phần 01

Service Registry (Server)

Central database lưu trữ network states. Eureka Server chạy độc lập, hỗ trợ peer-to-peer replication đảm bảo High Availability (HA).

Thành phần 02

Service Provider (Client)

Microservice cung cấp API. Lúc startup, Provider đăng ký network info. Định kỳ gửi Heartbeat duy trì liveness state.

Thành phần 03

Service Consumer (Client)

Consumer tải và cache cục bộ registry catalog. Khi thực thi request (VD: OpenFeign), tích hợp Load Balancer tự động chia tải qua danh sách IPs.

Act 04 — Case Study

KBM: Apply It

Service Discovery giúp KBM đạt được Elastic Scaling tự động khi xử lý tải thi trực tuyến.

Service Registry Solutions Comparison

Network Addressing Strategies
Tiêu chí Manual Hardcoded IPs Netflix Eureka Kubernetes DNS (CoreDNS)
Setup / Ops Effort Dễ (Không cần extra infra). Trung bình (Deploy 1 Eureka cluster). Cao (Yêu cầu K8s cluster).
Auto Scale-out Không (Requires manual config). Tự động khi service startup. Tự động (Native Kube-DNS).
Load Balancing Không (Hoặc Hardware Load Balancer). Client-side (Spring LoadBalancer). Server-side (K8s ClusterIP).
KBM Environment Deprecated. Local / Dev (Docker Compose). Production (Kubernetes).

Eureka Deployment Roadmap

Service Discovery Deployment Phases
Phase 1 · Tuần 1

Deploy Standalone Eureka Server

Khởi tạo Spring Boot + spring-cloud-starter-netflix-eureka-server. Disable self-registration (register-with-eureka: false).

Dự kiến: 1 dev × 2 ngày
Phase 2 · Tuần 2

Configure Automated Service Registration

Tích hợp spring-cloud-starter-netflix-eureka-client vào các downstream services. Gắn @EnableDiscoveryClient và map tới Eureka URL.

✓ Automated network registration
Phase 3 · Tuần 3

Integrate Feign Client & Client-side Load Balancing

Sử dụng @FeignClient(name = "service-id"). Tích hợp Spring Cloud LoadBalancer áp dụng Round-Robin load balancing.

Dự kiến: 1 dev × 3 ngày
Phase 4 · Tuần 4

Production Heartbeat Tuning

Tuning lease-expiration-duration-in-seconds (VD: 10s) giúp Gateway evict failed IPs khỏi cache nhanh chóng.

✓ Ensure High Fault Tolerance

Use Cases / Anti-patterns

✓
Use cases
  • Hệ thống phân tán với dynamic IPs.
  • Auto-scaling / containerized deployments.
  • Sử dụng Gateway / Feign Client để routing.
  • Centralized Health Tracking (Liveness/Readiness).
✗
Anti-patterns
  • Kiến trúc Monolith đơn giản.
  • Cloud-Native K8s (Nên dùng native Kube-DNS).
  • Static Infrastructure (VD: Gọi 3rd-party APIs).
  • Dự án nhỏ, cần minimize deployment footprint.
