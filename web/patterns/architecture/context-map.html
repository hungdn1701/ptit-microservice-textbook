Act 01

The Problem

Trong hệ thống phân tán với nhiều team, mỗi team duy trì model riêng cho các khái niệm chung, dẫn đến rủi ro tích hợp khi thiếu tính minh bạch về dependency.

Context

Ambiguous Ubiquitous Language

"User" ở Auth là account đăng nhập. "User" ở Core là learner. Cùng khái niệm, khác model gây ra silent bugs khi tích hợp.

Dependency

Implicit Integration

Assignment gọi Core API nhưng thiếu document. Core refactor field userId → learnerId làm Assignment crash trên production.

Database

Shared Database Anti-pattern

Core và Assignment dùng chung DB schema. Schema thay đổi gây break queries liên team, dẫn đến cản trở refactor.

Document

Undocumented Relationships

Thiếu định nghĩa rõ ràng về upstream và downstream. Thiếu "bản đồ" kiến trúc gây integration chaos và khó khăn trong việc debug.

Act 02

The Pattern

Context Map là bản đồ toàn cục hệ thống, hiển thị các Bounded Contexts, ranh giới, và mô hình tích hợp (upstream/downstream, shared kernel, anti-corruption layer). Đây là tài liệu sống, không phải sơ đồ tĩnh.

— Eric Evans, Domain-Driven Design [6, Ch.14] · 2003

Các Integration Pattern phổ biến xác định mối quan hệ giữa các Bounded Contexts:

U — Upstream (nhà cung cấp) D — Downstream (phụ thuộc) SK — Shared Kernel CF — Conformist ACL — Anti-Corruption Layer OHS — Open Host Service
Upstream (U)

Provider

Cung cấp API/model. Thay đổi ở Upstream trực tiếp ảnh hưởng đến Downstream. VD: Auth Service là Upstream của Core.

Downstream (D)

Consumer

Phụ thuộc vào Upstream. Downstream phải adapt theo thay đổi từ Upstream hoặc dùng ACL để bảo vệ domain model.

ACL

Anti-Corruption Layer

Lớp chuyển đổi tại Downstream. Convert model của Upstream sang domain model nội bộ, ngăn sự "ô nhiễm" logic.

Migration Timeline

Chuyển từ implicit coupling sang explicit Context Map

Tuần 1 · Phase 0

Event Storming

Tổ chức cross-team workshop. Xác định Bounded Contexts, aggregates, và domain events. Output: Draft Context Map.

Effort: Toàn team
Tuần 2 · Phase 1

Document as-is architecture

Xây dựng Context Map chính thức. Xác định upstream/downstream, shared kernel, và implicit dependencies. Thiết lập architecture baseline.

Output: context-map.md trong repo
Tháng 1 · Phase 2

Triển khai Contract Tests cho critical integration points

Tích hợp Pact consumer-driven contract tests (Auth → Core, Assignment). CI tự động verify backward compatibility khi thay đổi API.

✓ Safe API evolution
Tháng 2+ · Phase 3

Triển khai ACL cho Core → Assignment

Assignment xây dựng ACL để translate Core objects sang internal domain model. Core có thể refactor an toàn không gây break Assignment.

✓ Team autonomy achieved

Khi nào dùng — Khi nào không

Yes
Phù hợp khi
  • Hệ thống có nhiều team cùng tham gia phát triển
  • Domain model phức tạp, độ chồng chéo khái niệm cao
  • Chuẩn bị migrate monolith sang microservices
  • Phân tích integration risk trước khi refactor
No
Không cần thiết khi
  • Hệ thống quy mô nhỏ, 1 team, 1 domain
  • Domain model đơn giản, rõ ràng
  • Giai đoạn Prototype/MVP với requirement thay đổi nhanh
